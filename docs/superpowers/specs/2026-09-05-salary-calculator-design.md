# 工资计算网页工具 — 设计文档

日期：2026-09-05
状态：待用户审阅

## 1. 背景与目标

做一个纯前端工资计算网页工具，输入月薪、薪数、年终奖、工作城市（上海/杭州）、公积金缴存比例，按 **2026 年**最新社保公积金政策和现行个税规则，输出逐月税前/税后明细、年度总到手、社保公积金缴纳明细。参考形态：https://gjupai.com/salary-calculator（即时计算 + 月度明细 + 图表）。

非目标：不做用户系统、不做后端存储、不做多城市扩展（架构上留配置入口即可）。

## 2. 需求与已确认口径

### 2.1 输入

| 输入项 | 形式 | 默认值 | 说明 |
|---|---|---|---|
| 工作城市 | 上海 / 杭州 Tab | 上海 | 切换后政策参数、公积金比例范围联动 |
| 月薪（税前） | 数字输入 | 20000 | 元/月 |
| 薪数 | 下拉 12/13/14/15/16 | 12 | 超出 12 的部分视为"第 N 薪"，按奖金单独计税 |
| 年终奖 | 数字输入 | 0 | 元，发放月固定为 12 月 |
| 基本公积金比例 | 下拉（按城市范围） | 最高档 | 单位=个人同比例；上海 5%-7%，杭州 5%-12% |
| 补充公积金比例 | 下拉 0/1/.../9 | 0 | 输入范围统一 1%-9%，默认 0；上海政策上限 5%，杭州以单位实际执行为准（页脚注明） |
| 每月专项附加扣除 | 数字输入 | 0 | 房租/房贷、子女教育、赡养老人等每月合计 |
| 社保基数 | 自动（可自定义覆盖） | clamp(月薪) | 低于下限或高于上限时自动 clamp；自定义时显示橙色提示 |
| 公积金基数 | 自动（可自定义覆盖） | clamp(月薪) | 同上，公积金上下限与社保不同 |

### 2.2 输出

1. **汇总卡片**：年度总到手（大字）；年终奖计税方案对比（A/B/C 三方案，显示各方案年度总个税，最优绿色高亮 + 推荐标签）
2. **月度明细表**：1-12 月每行 `税前 | 三险一金(个人) | 个税 | 税后`；13 薪、年终奖在 12 月单独成行；底部合计行
3. **社保公积金卡片**：个人 / 单位两列，各险种月度 + 年度合计（养老、医疗、失业、基本公积金、补充公积金；工伤/生育仅单位列）
4. **图表**：按月堆叠柱状图（税后 + 个税 + 个人社保公积金），recharts
5. **页脚**：政策来源链接 + 免责声明

### 2.3 已确认的计税口径

- **年终奖**：A 单独计税 / B 并入综合所得 / C 13 薪+年终奖合并一笔奖金单独计税，三方案都算并对比。
- **13 薪（含 14/15/16 薪，每多一个月薪算一笔）**：按全年一次性奖金单独计税，不并入月薪流水；与年终奖的合并（方案 C）作为对比项展示。
- 严格个税口径下"全年一次性奖金单独计税一年只能用一次"，方案 A 中多笔奖金各自单独计税属常用简化口径，页面注明；方案 C 合并为一笔则完全符合政策。
- 月薪流水固定 12 个月；各笔奖金发放月固定 12 月（简化，后续可加发放月选择）。

### 3.4 已知简化（明确决策，非遗漏）

- 医疗单位比例已含生育保险，生育不再单列。
- 不含大病医疗救助、长期护理保险等小额固定费（合计每月约 3-4 元，不影响到手主口径）；如后续需要可在 policy 配置中加固定费项。
- 工伤展示费率取典型档，页面注明"因行业而异"。

数据流（单向，全部纯函数）：

```
Inputs → resolveBases(基数 clamp) → socialMonthly / housingFundMonthly
      → buildPayroll(12 个月工资流水 + 奖金)
```

## 5. 计算规则（公式级）

### 5.1 基数

```
base_social = clamp(user_social_base ?? monthly_salary, social.min, social.max)
base_hf     = clamp(user_hf_base     ?? monthly_salary, hf.min,     hf.max)
```

### 5.2 社保（每月，单位与个人同基数）

- 个人月缴 = base_social × (8% + 2% + 0.5%)，四舍五入到分
- 单位月缴 = base_social × (16% + 医疗单位比例 + 0.5% + 工伤展示费率)，四舍五入到分

### 5.3 公积金（每月，单位与个人同基数）

- 基本公积金（个人 = 单位）= round(base_hf × 基本比例)，四舍五入到**元**（沪公积金规则）
- 补充公积金（个人 = 单位）= round(base_hf × 补充比例)，四舍五入到元
- 个人缴存合计 = 基本 + 补充；单位缴存合计同额

### 5.4 个税 — 月薪（累计预扣法）

第 m 月（m = 1..12）：

```
cum_income   = Σ_{1..m} 税前月薪
cum_deduct   = 5000 × m + Σ_{1..m} 个人三险一金 + Σ_{1..m} 专项附加扣除
cum_taxable  = cum_income − cum_deduct  (下限 0)
cum_tax      = cum_taxable × 年度税率表税率 − 速算扣除数
monthly_tax  = cum_tax − Σ_{1..m-1} 已预缴税
```

### 5.5 个税 — 奖金（全年一次性奖金单独计税）

```
tax(bonus) = bonus × 月度税率表(bonus ÷ 12).rate − 月度税率表(bonus ÷ 12).quickDeduction
```

### 5.6 三方案对比

| 方案 | 月薪流水 | 13 薪 | 年终奖 |
|---|---|---|---|
| A | 累计预扣 | 单独计税 | 单独计税 |
| B | 累计预扣（年终奖并入 12 月税前收入） | 单独计税 | —（并入流水） |
| C | 累计预扣 | —（与年终奖合并） | 与 13 薪合并为一笔奖金单独计税 |

年度总个税 = 月薪流水个税 + 奖金个税（按方案），取最小者标记"推荐"。

### 5.7 汇总

```
总到手 = Σ 每月税后 + 13 薪税后 + 年终奖税后   （按推荐方案）
个人社保公积金年度合计 / 单位社保公积金年度合计（单位含工伤、不含个人为 0 的项）
税前年总包 = 月薪 × 12 + 13 薪 + 年终奖
```

### 5.8 精度

- 社保：到分（round 2 位）；公积金：到元（round 0 位）
- 个税：到分；金额展示：千分位，保留 2 位小数

## 6. UI 规范

- 单页两栏（桌面）/ 上下堆叠（移动端 ≤ 768px）
- 左侧输入卡片；右侧自上而下：汇总卡片（含方案对比表）、月度明细表、社保公积金卡片、堆叠柱状图
- 即时计算，无提交按钮；数字输入校验非负
- 基数自定义覆盖时输入框橙色描边 + "已自定义，偏离默认 clamp 值"提示
- 方案对比：三行表格（方案 / 年度总个税 / 年度总到手），最优行绿色高亮 + "推荐"徽标
- 中文界面；颜色语义：绿=到手，红=个税，蓝=社保公积金
- 页脚：政策参数来源链接 + "按 2026 年政策估算，实际以单位申报为准，仅供参考"

## 7. 测试规范（Vitest，只测计算层）

1. **tax.ts**
   - 累计预扣：构造月薪 30000、无扣除用例，断言逐月个税单调不减、12 月累计 = 年度表直算结果
   - 专项附加扣除、三险一金扣除正确进入 cum_deduct
   - 奖金单独计税：36000/36001 边界跳档验证（36000 → 1080 元，36001 → 3390.1 元）
   - 并入综合所得（方案 B）：12 月税前加奖金后重跑累计预扣
2. **social.ts**
   - 基数 clamp 三态：低于下限 / 中间 / 高于上限
   - 公积金到元、社保到分的 rounding
   - 自定义基数生效且仍被 clamp
3. **annual.ts**
   - 12 个月流水合计与汇总卡片数值一致
   - 三方案年度总个税 = 各部分之和；推荐方案 = 最小值
   - 验收样例：上海月薪 30000、13 薪、年终奖 100000、公积金 7%、无补充、无专项附加——实施时先手工核算出各月期望值并固化为快照测试
4. **policy**
   - 参数完整性校验（所有必填字段存在、比例 0-1 之间、下限 < 上限）

## 8. 风险与后续
